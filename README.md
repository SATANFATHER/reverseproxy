# Go SOCKS5 Proxy with Remote Deployment Script

## Overview

This project provides a simple but functional SOCKS5 proxy server written in Go, along with a Bash script for easy deployment and management of this proxy on multiple remote Linux servers via SSH. The proxy supports optional username/password authentication.

## Features

### SOCKS5 Proxy Server (`main.go`)

*   **SOCKS5 Protocol Compliance:** Implements the SOCKS5 protocol (RFC 1928).
*   **Authentication:**
    *   Supports "No Authentication Required" method (0x00).
    *   Supports "Username/Password Authentication" method (0x02) as per RFC 1929.
    *   If server credentials are provided, it enforces authentication. Otherwise, it allows connections without authentication if the client supports it.
*   **Command Support:** Handles the `CONNECT` command.
*   **Address Types:** Supports IPv4 (ATYP 0x01) and Domain Name (ATYP 0x03) address types for destination targets.
*   **Concurrency:** Uses Goroutines to handle multiple client connections concurrently, ensuring efficient and non-blocking operation.
*   **Logging:** Basic logging for server events, new connections, authentication status, and connection forwarding.
*   **Configurable:** Listening host, port, and SOCKS5 credentials can be set via command-line arguments.

### Deployment Script (`deploy_proxy.sh`)

*   **Remote Deployment:** Deploys the compiled SOCKS5 proxy binary to one or more remote Linux servers using SSH and SCP.
*   **Status Checking:** Checks if an instance of the proxy (matching a specific executable path) is already running on configured ports before attempting deployment.
*   **Port Management:**
    *   Checks for available network ports on remote servers from a predefined list.
    *   Attempts to start the proxy on the first available port found.
*   **Automated Startup:** Starts the proxy on the remote server using `nohup` to run it in the background and persist after the SSH session ends.
*   **Remote Logging:** Redirects the remote proxy server's standard output and error to a log file on the remote server (e.g., `/tmp/socks5proxy_<port>.log`).
*   **Configuration:** Key parameters like SSH user, remote paths, SOCKS5 proxy credentials (for deployed instances), and target ports are configurable within the script.
*   **Deployment Logging:** Logs all its actions, progress, and outcomes to both the console and a local `deployment.log` file.
*   **Real-time Progress:** Shows progress in the console as it processes each server.

## Prerequisites

### SOCKS5 Proxy Server (Go)

*   **Go Compiler:** Version 1.18 or higher (for `go build`).
*   **Basic Go knowledge** (to understand the source code).

### Deployment Script (`deploy_proxy.sh`)

*   **Bash Shell:** A standard Linux or macOS environment with Bash.
*   **SSH Client:** OpenSSH client (or compatible) installed on the machine running the script.
*   **SCP Client:** Secure Copy Protocol client (usually part of OpenSSH).
*   **Remote Server Access:**
    *   SSH access to the target Linux servers.
    *   Key-based SSH authentication is recommended for automated deployment without password prompts. If not, you might need to use `ssh-agent` or modify the script for password handling (not included by default).
    *   Sudo privileges on remote servers might be needed if deploying to restricted directories or managing system services (though this script deploys to `/tmp` by default).

## Setup and Compilation (Go Proxy)

To compile the SOCKS5 proxy server:

1.  **Navigate to the project directory** where `main.go` is located.
2.  **Build the Go program:**
    ```bash
    go build -o socks5proxy main.go
    ```
    For a statically linked binary (recommended for easier deployment, reducing dependencies on remote servers):
    ```bash
    CGO_ENABLED=0 go build -ldflags="-s -w" -o socks5proxy main.go
    ```
    The `-ldflags="-s -w"` flag helps reduce the binary size by stripping debug symbols.

This will create an executable file named `socks5proxy` in the current directory.

## Proxy Server Configuration and Usage

The `socks5proxy` binary can be run directly from the command line.

### Command-Line Arguments:

`./socks5proxy [host] [port] [username] [password]`

*   `host` (optional): The IP address for the proxy to listen on. Defaults to `0.0.0.0` (all interfaces).
*   `port` (optional): The port number for the proxy to listen on. Defaults to `1080`.
*   `username` (optional): Username for SOCKS5 authentication. If provided along with `password`, authentication is enabled.
*   `password` (optional): Password for SOCKS5 authentication.

### Examples:

*   **Run without authentication on port 1080:**
    ```bash
    ./socks5proxy
    ```
    (or `./socks5proxy 0.0.0.0 1080`)

*   **Run with username "user1" and password "pass123" on port 8888:**
    ```bash
    ./socks5proxy 0.0.0.0 8888 user1 pass123
    ```

### Authentication Modes:

*   **No Authentication:** If `username` and `password` are NOT provided when starting the proxy, it will allow clients that support the "No Authentication Required" method.
*   **Username/Password Authentication:** If `username` and `password` ARE provided, the proxy will require clients to authenticate using these credentials via the "Username/Password Authentication" method.

## Deployment Script Configuration and Usage (`deploy_proxy.sh`)

The `deploy_proxy.sh` script automates the deployment of the `socks5proxy` binary to remote servers.

### Configuration:

Before running, you might need to adjust variables at the top of `deploy_proxy.sh`:

*   `SSH_USER`: Your SSH username for connecting to remote servers (e.g., `SSH_USER="your_ssh_user"`). If empty, it uses your current local username or relies on your SSH config.
*   `REMOTE_PROXY_EXEC_PATH`: The full path where the `socks5proxy` binary will be copied and run on the remote server. Defaults to `/tmp/socks5proxy_deploy_instance`.
*   `PROXY_SOCKS_USER`: The username that the *deployed SOCKS5 proxy instances* will use for their own authentication. Leave empty for no authentication on deployed proxies.
*   `PROXY_SOCKS_PASS`: The password for the deployed SOCKS5 proxy instances.
*   `PROXY_PORTS`: An array of ports the script will try to use on the remote server (e.g., `(1080 1081 8080 8888)`).

### Making the Script Executable:

```bash
chmod +x deploy_proxy.sh
```

### Running the Script:

```bash
./deploy_proxy.sh <server_ip1> [server_ip2] ... [server_ipN]
```
*   Replace `<server_ip1>`, `<server_ip2>`, etc., with the actual IP addresses or resolvable hostnames of your remote servers.

**Example:**
```bash
./deploy_proxy.sh 192.168.1.101 192.168.1.102
```

The script will output its progress to the console and log detailed information to `deployment.log` in the same directory.

## Deployment Process (Conceptual Flow)

The `deploy_proxy.sh` script performs the following steps for each target server:

1.  **Connect via SSH:** Establishes an SSH connection (using `SSH_USER` if configured).
2.  **Check Existing Proxy:** Iterates through `PROXY_PORTS` to see if an instance of the proxy (matching `REMOTE_PROXY_EXEC_PATH`) is already running on any of those ports.
    *   If found, logs this and skips deployment for that server.
3.  **Find Available Port:** If no existing proxy is found, it checks the ports in `PROXY_PORTS` one by one to find one that is not currently in use on the remote server.
    *   If no listed port is available, logs an error and skips deployment for that server.
4.  **Copy Proxy Binary:** Uses `scp` to copy the local `socks5proxy` binary (from `PROXY_BINARY_PATH`) to the `REMOTE_PROXY_EXEC_PATH` on the remote server.
5.  **Set Permissions:** Makes the copied binary executable on the remote server (`chmod +x`).
6.  **Start Proxy:** Executes the proxy binary on the remote server using `nohup`. The proxy is configured to listen on `0.0.0.0` and the selected available port, and with the specified `PROXY_SOCKS_USER` and `PROXY_SOCKS_PASS` (if any). Output is redirected to a remote log file (e.g., `/tmp/socks5proxy_<port>.log`).
7.  **Verify Deployment:** After a short pause, it performs another check to see if the proxy process has started successfully.
8.  **Log Outcome:** Logs the success or failure of the deployment for the server.

## How It Works (Briefly)

*   **SOCKS5 Proxy:** The Go application listens for incoming TCP connections. When a SOCKS5 client connects, it performs the SOCKS5 handshake (version negotiation, authentication method selection, optional username/password verification). If successful and a `CONNECT` request is received, the proxy establishes a TCP connection to the client's desired destination server. It then relays data between the client and the destination server in both directions using Goroutines for concurrent `io.Copy` operations.
*   **Deployment Script:** The Bash script leverages standard SSH and SCP commands to interact with remote servers. It automates the process of checking server state, transferring files, and executing commands remotely.

## Troubleshooting (Basic)

*   **Deployment Script Fails:**
    *   Check `deployment.log` for detailed error messages.
    *   Ensure `SSH_USER` (if used) is correct and you have SSH access to the servers (try a manual `ssh user@server_ip` command).
    *   Verify that key-based authentication is set up for SSH, or that your `ssh-agent` is configured if your keys have passphrases.
    *   Ensure the `socks5proxy` binary exists at `PROXY_BINARY_PATH` and is executable.
    *   Check for firewall rules on remote servers that might be blocking SSH, SCP, or the chosen proxy ports.
*   **Proxy Not Working After Deployment:**
    *   SSH into the remote server.
    *   Check the remote proxy log file (e.g., `/tmp/socks5proxy_<port>.log`) for any errors from the proxy itself.
    *   Use `ps aux | grep socks5proxy` or `pgrep -af socks5proxy` to see if the process is running.
    *   Use `ss -tlpn | grep <port>` or `netstat -tlpn | grep <port>` to verify the proxy is listening on the expected port.
*   **Authentication Issues:**
    *   Double-check the `PROXY_SOCKS_USER` and `PROXY_SOCKS_PASS` variables in `deploy_proxy.sh` if you intend to use authentication on deployed proxies.
    *   Ensure your SOCKS5 client is configured with the correct credentials.
*   **"No acceptable authentication methods" error from client:**
    *   If the proxy requires authentication, ensure your client is configured to use username/password.
    *   If the proxy *doesn't* require authentication, ensure your client is configured to use "no authentication" or "SOCKS5 (no auth)".
